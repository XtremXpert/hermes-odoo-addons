Téléphonie Wazo

Connecteur Wazo Platform, module d’un tenant Wazo.

  • connexion au serveur Wazo (URL, jeton d’API, tenant) par les réglages ;
  • création d’utilisateurs Wazo (ligne SIP, poste, endpoint, messagerie vocale) depuis un contact Odoo ;
  • création de groupes d’appel (ring groups) : poste pris dans la plage des groupes du contexte, membres rattachés par utilisateur Wazo et ordonnés par priorité de sonnerie ;
  • inventaire des postes du contexte : rattachements, postes orphelins, correspondance avec les fiches Odoo ;
  • journal d’appels synchronisé depuis wazo-call-logd (tâche planifiée et bouton manuel), statistiques d’appels par contact ;
  • softphone WebRTC dans Odoo (moteurs sip.js et SDK Wazo).

Les plages d’extensions sont lues dans Wazo (contextnumbers) au lieu d’être recopiées : un poste hors plage, d’un autre type, ou déjà en service, est refusé avant toute écriture distante.

Use Cases / Context

Le module de l’usage téléphonique d’un tenant : ses postes, son journal d’appels, son tableau de bord et son téléphone dans le navigateur. Il ne crée pas l’infrastructure — le tenant, son contexte et ses plages sont l’affaire de wazo_server — et il ne crée pas non plus les modèles d’exploitation, qui vivent dans wazo_tenant : il apporte la couche d’usage côté Odoo et les extensions dont un tenant a besoin. C’est le module qu’installe le client, avec wazo_tenant, et jamais wazo_server.

Techniquement, le module n’a aucun modèle à lui : il étend wazo.user, wazo.cdr, res.users et res.config.settings. Le softphone parle directement à Wazo en SIP-over-WSS, sans relay : pour un endpoint généré par Wazo, l’AOR de l’en-tête From est le nom de l’endpoint et non l’extension, d’où deux valeurs séparées (aor et auth_user). Le pont vers le module voip d’Odoo Enterprise est optionnel : sans ce module, il est un no-op, et wazo_phone reste utilisable avec un poste SIP classique.

Les fichiers d’actifs sont chargés « après le chargeur » (after web/static/src/module_loader.js) parce qu’Odoo trie les modules du paquet et place wazo_phone avant web : sans cette directive, odoo.define n’existe pas encore et le client web reste blanc sans erreur serveur. Les bibliothèques static/lib/sip.js et static/lib/wazo-sdk.js sont vendorisées ; le SDK est chargé à la demande, seulement quand le moteur SDK est choisi. Le module dépend de wazo_tenant, web et mail, et documente ses écrans dans doc/ADMINISTRATEUR.md et doc/UTILISATEUR.md.

Installation

Aucune dépendance externe : le manifeste ne déclare ni external_dependencies Python ni binaire, et les bibliothèques du softphone (sip.js, SDK Wazo) sont vendorisées dans static/lib/. Le module dépend de wazo_tenant, web et mail et s’installe comme un module Odoo standard.

Le module voip d’Odoo Enterprise est facultatif : il n’est pas déclaré en dépendance, et le pont vers ce module est un no-op s’il est absent. Pour le softphone Enterprise, installer voip, puis activer le pont dans les réglages (voir Configuration).

Configuration

  1. Inscrire les utilisateurs aux groupes du module : les menus sont rangés derrière eux et l’administrateur n’y est pas d’office. Le groupe « Téléphonie Wazo : Gestionnaire » implique « Utilisateur ».
  2. Dans Réglages → Téléphonie Wazo, renseigner l’URL du serveur, le jeton d’API et le tenant, puis tester la connexion. Côté tenant, le jeton est le jeton de tenant fabriqué par wazo_server.

Softphone dans le navigateur (pont voip)

La section « Pont softphone » des réglages n’apparaît que si le module voip d’Enterprise est installé et que le serveur Wazo expose le transport wss :

  • Softphone (voip) : active le pont (paramètre wazo.softphone_enabled, vrai par défaut) ; les champs suivants sont masqués quand il est faux.
  • URL WebSocket (wss) : wazo.ws_url ; à défaut, l’URL est dérivée de wazo.url (voie native v3, endpoint /api/asterisk/ws).
  • Domaine SIP (PBX) : wazo.pbx_domain, utilisé dans les URI SIP ; « asterisk » par défaut.
  • Créer le provider et propager les identifiants : crée ou met à jour le provider « Wazo » et réapplique les identifiants SIP des utilisateurs synchronisés.

Usage

Pour utiliser ce module, il faut :

  1. Attribuer le groupe Téléphonie Wazo : Utilisateur (ou Gestionnaire) à l’usager, et lier son compte Odoo à un poste Wazo synchronisé.
  2. Ouvrir Téléphonie Wazo > Tableau de bord : indicateurs sur 7, 30 ou 90 jours (appels, manqués, taux de réponse entrant, temps d’appel) pour son poste ; un gestionnaire voit en plus la section Équipe et la répartition par poste.
  3. Consulter Téléphonie Wazo > Journal d’appels (fourni par wazo_tenant) : sens, appelant, destination, appel répondu, durée et contact reconnu. Le journal est alimenté par la synchronisation, manuelle ou planifiée, pas en temps réel.
  4. Si l’administrateur a activé le softphone, ouvrir le panneau par l’icône téléphone de la barre système : composer un numéro et cliquer Appeler, répondre avec Répondre, terminer avec Raccrocher. L’onglet Journal du panneau liste les appels récents.
  5. Cliquer Appeler sur un numéro dans n’importe quel champ téléphone d’Odoo (click-to-call) : l’appel part par le softphone si l’usager a un poste Wazo configuré, sinon par le lien tel: du navigateur.
  6. En fin d’appel, une note est déposée sur la fiche du contact reconnu ; un appel entrant manqué crée une activité « Appel » et une notification.

Le pont softphone (activation, moteur, URL WebSocket, domaine SIP) se règle dans Réglages > Téléphonie Wazo.

Known issues / Roadmap

Limites connues

  • Journal non temps réel : il se met à jour à la synchronisation, manuelle ou planifiée ; doc/UTILISATEUR.md le dit explicitement.
  • Lecture seule sur les postes : l’utilisateur ne modifie ni les postes ni la configuration (doc/UTILISATEUR.md, « Rappels et limites »).
  • Pont softphone Enterprise optionnel : le module voip d’Enterprise n’est pas une dépendance. Sans lui, le pont est un no-op ; la section de réglages n’apparaît que si voip est installé et que le serveur Wazo expose wss.
  • Bibliothèques vendorisées : static/lib/sip.js et static/lib/wazo-sdk.js sont des fichiers tiers maintenus hors du dépôt ; le SDK est servi dans son propre paquet (wazo_phone.assets_sdk) et chargé à la demande.
  • Ordre des actifs imposé : les fichiers doivent rester après web/static/src/module_loader.js ; modifier la déclaration des actifs peut blanchir le client web sans erreur serveur (commentaire du manifeste).
  • Ancienne table conservée : la migration 20.0.3.0.0 laisse en place wazo_ring_group_wazo_user_rel comme donnée de retour arrière ; elle est inerte, plus aucun modèle ne la déclare.
  • Couverture JavaScript à part : les tests du softphone sont des tests Node (static/tests/), qu’aucun test Python ne voit, et rien ne charge le client web dans un navigateur (voir la note du README.md du dépôt).
  • Statut ``Beta`` : development_status vaut Beta.

Pistes
