Point d'entrée HTTP qui reçoit le courriel brut (RFC 5322) d'un relais
externe et le remet à ``mail.thread.message_process``, comme le ferait
le relèvement IMAP, mais sans boîte à relever ni compte utilisateur :
l'appel est authentifié par un **jeton**.

Son client principal est ``relais-courriel``, le relais LMTP déployé à
côté de Mailcow (dépôt ``diverse-odoo``, ``infra/relais-courriel/``) :
Postfix lui remet le courriel des adresses d'Odoo, il le pousse ici et
traduit la réponse en code SMTP.

Routes
------

Toutes sous ``/diverse/mail-gateway/``, en HTTPS seulement (sauf réglage
contraire, voir Configuration).

+-------------------+------------------+-------------------------------+
| Route             | Authentification | Rôle                          |
+===================+==================+===============================+
| ``GET /health``   | aucune           | sonde de vie, répond toujours |
|                   |                  | ``200``                       |
+-------------------+------------------+-------------------------------+
| ``POST /check``   | jeton            | vérifie le jeton, sans rien   |
|                   |                  | écrire                        |
+-------------------+------------------+-------------------------------+
| ``POST /process`` | jeton            | remet le message brut à       |
|                   |                  | ``message_process``           |
+-------------------+------------------+-------------------------------+

En-têtes de ``/process`` :

+--------------------------------------+--------+------------------------------+
| En-tête                              | Requis | Rôle                         |
+======================================+========+==============================+
| ``X-Mail-Gateway-Token``             | oui    | le jeton                     |
+--------------------------------------+--------+------------------------------+
| ``Content-Type``                     | oui    | ``message/rfc822``           |
+--------------------------------------+--------+------------------------------+
| ``X-Mail-Gateway-Save-Original``     | non    | ``1`` : garder le message    |
|                                      |        | d'origine en pièce jointe    |
+--------------------------------------+--------+------------------------------+
| ``X-Mail-Gateway-Strip-Attachments`` | non    | ``1`` : retirer les pièces   |
|                                      |        | jointes                      |
+--------------------------------------+--------+------------------------------+

Réponses de ``/process`` :

+---------+-------------------------------------------------------+-----------------------------+
| HTTP    | Corps                                                 | Cas                         |
+=========+=======================================================+=============================+
| ``200`` | ``{"ok": true, "result": <id>, "message_id": "<…>"}`` | message remis à un fil      |
+---------+-------------------------------------------------------+-----------------------------+
| ``400`` | ``{"ok": false, "error": "bad_request"}``             | corps vide ou illisible     |
+---------+-------------------------------------------------------+-----------------------------+
| ``401`` | ``{"ok": false, "error": "unauthorized"}``            | jeton absent, invalide,     |
|         |                                                       | expiré ou révoqué           |
+---------+-------------------------------------------------------+-----------------------------+
| ``403`` | ``{"ok": false, "error": "forbidden"}``               | requête en HTTP clair       |
+---------+-------------------------------------------------------+-----------------------------+
| ``422`` | ``{"ok": false, "error": "no_route"}``                | aucun alias ni fil ne       |
|         |                                                       | correspond                  |
+---------+-------------------------------------------------------+-----------------------------+
| ``500`` | ``{"ok": false, "error": "internal"}``                | erreur inattendue           |
+---------+-------------------------------------------------------+-----------------------------+

Sécurité
--------

- Le jeton (``secrets.token_urlsafe(32)``) n'est montré **qu'une fois**,
  à sa création : seule son empreinte SHA-256 est stockée, comparée en
  temps constant.
- Chaque jeton se révoque, peut expirer, et garde sa date et son adresse
  de dernier usage.
- Seul ``message_process`` s'exécute en superutilisateur : un jeton volé
  permet de créer des messages, pas de lire ni de modifier la base.
- Les journaux ne contiennent jamais le jeton.

Use Cases / Context
===================

Le courrier entrant d'Odoo arrive normalement par un relèvement IMAP,
avec une boîte et un compte utilisateur à gérer. Ici, un relais LMTP
externe (``relais-courriel``) reçoit déjà le courrier des adresses Odoo
: il lui faut un point d'entrée HTTP qui le remette à
``message_process``, authentifié par un jeton et non par une session.
D'où un module séparé de ``imap_client``, qui relève une boîte, et de
``mailcow``, qui administre un serveur de messagerie.

Trois routes sous ``/diverse/mail-gateway/`` : ``health`` sans
authentification, ``check`` et ``process`` protégées par l'en-tête
``X-Mail-Gateway-Token``. Le jeton n'est jamais stocké en clair : seule
son empreinte SHA-256 est conservée, et la comparaison parcourt toute la
liste des jetons actifs en temps constant, sans sortie anticipée. Seul
``message_process`` tourne en superutilisateur ; un jeton volé permet
donc de créer des messages, pas de lire la base. Le HTTPS est exigé,
sauf paramètre ``diverse_mail_gateway.allow_http`` pour un banc d'essai.

Le code de réponse est traduit en décision SMTP par le relais : 200
livré, 422 aucune route, 401 jeton invalide ou expiré, 400 corps
illisible, 500 erreur interne. Le module est un fork renommé de
``bemade_mail_gateway`` (Bemade Inc., AGPL-3) porté sur Odoo 20 ; il
dépend de ``base`` et ``mail`` et n'ajoute aucune dépendance Python.

Installation
============

Aucune dépendance externe : le module ne déclare ni dépendance Python ni
binaire (``external_dependencies`` absent) et s'installe comme un module
Odoo standard. Le contrôleur n'utilise que la bibliothèque standard
(``email``, ``hashlib``, ``hmac``, ``secrets``).

Le relais doit joindre ``/diverse/mail-gateway/process`` en HTTPS ;
derrière un mandataire qui termine TLS, Odoo doit tourner avec
``--proxy-mode`` (voir Configuration). Installer le module avant de
configurer le relais, pour que le jeton puisse être créé et testé depuis
Odoo.

Configuration
=============

1. Donner le groupe **Mail Gateway Administrator** à la personne qui
   gère les jetons (il implique Administration / Paramètres).
2. En mode développeur, ouvrir *Paramètres → Technique → Mail Gateway →
   Generate Token*, saisir un libellé (par exemple ``relais-courriel``)
   et cliquer **Generate**.
3. Copier le jeton affiché **tout de suite** : il ne sera plus jamais
   visible. Le placer dans la configuration du relais, jamais dans un
   dépôt.
4. Vérifier depuis le relais : ``POST /diverse/mail-gateway/check`` avec
   l'en-tête ``X-Mail-Gateway-Token`` doit répondre ``{"ok": true, …}``.

Derrière un mandataire qui termine TLS, Odoo doit tourner avec
``--proxy-mode``. Pour un banc d'essai en HTTP clair seulement, le
paramètre système ``diverse_mail_gateway.allow_http`` à ``True`` lève le
refus du HTTP.

Usage
=====

Pour utiliser ce module, il faut :

1. Configurer le relais courriel avec un jeton (voir Configuration) :
   c'est lui, et non un utilisateur Odoo, qui s'authentifie auprès
   d'Odoo.
2. Laisser le relais remettre le courriel brut sur
   ``POST /diverse/mail-gateway/process`` ; Odoo le traite comme un
   message entrant et l'attache au fil correspondant, qui apparaît dans
   le chatter de l'objet concerné.
3. Suivre les jetons dans *Paramètres* > *Technique* > *Mail Gateway* >
   *Tokens* (en mode développeur) : nom, date et adresse du dernier
   usage, nombre d'utilisations, expiration, et bascule *Actif*.
4. Révoquer un jeton depuis sa fiche avec **Revoke** : le relais reçoit
   alors ``401`` à son prochain appel.
5. Retrouver les jetons jamais utilisés ou proches de l'expiration avec
   les filtres *Never used* et *Expiring soon (next 30d)*.

``GET /diverse/mail-gateway/health`` répond toujours ``200`` : c'est la
sonde de vie du service, sans authentification.

Known issues / Roadmap
======================

Le champ ``allowed_ips`` existe mais n'est pas appliqué : son aide le
dit (« Enforced in V2; field present for forward compatibility »). Aucun
compteur, aucune limitation de débit : un jeton valide peut appeler
``process`` autant de fois que le relais le fait.

Le jeton n'est montré qu'une fois, à sa création : seule l'empreinte est
stockée, donc un jeton perdu ne se retrouve pas — il faut le révoquer et
en générer un autre. ``Revoke`` désactive sans supprimer, ce qui
conserve la trace d'usage mais laisse la ligne en base.

Le module ne traite que l'entrant : aucun envoi, aucune gestion de file
d'attente. Le HTTPS est refusé par défaut ; derrière un mandataire qui
termine TLS, Odoo doit tourner avec ``--proxy-mode``. ``GET /health``
répond sans authentification et expose la version du module et d'Odoo :
c'est une sonde de vie assumée, pas une route à exposer largement.
