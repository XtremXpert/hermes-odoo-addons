Rend visibles dans l'écran **Applications** les modules qui n'y
apparaissent jamais, quelle que soit la recherche.

- Le panneau de gauche de l'écran Applications filtre toujours sur un
  type de module : « Applications officielles » (``official``, par
  défaut) ou « Secteurs d'activité » (``industries``). Il n'a pas
  d'option « tous ».
- Un module enregistré pendant un démarrage qui met la base à jour
  (``-i``, ``-u``, nouveau paquet Odoo) l'est avant le chargement de
  ``base_import_module``, qui porte le champ ``module_type``. Son type
  reste vide, et le module n'entre dans aucun des deux filtres. Constaté
  le 2026-10-19 : 35 modules sur maison (dont ``mailcow_admin``), 137
  sur la production de diverse-cite.
- À chaque chargement du registre, le module donne le type ``official``
  aux modules dont le type est vide. Les modules ``industries`` ne sont
  pas touchés.

Use Cases / Context
===================

L'écran Applications d'Odoo 20 ne montre que les modules dont le type
vaut ``official`` ou ``industries`` : le panneau de gauche n'offre
aucune option « tous ». Or un module enregistré pendant un démarrage qui
met la base à jour l'est avant le chargement de ``base_import_module``,
qui porte le champ ``module_type`` ; sa valeur reste NULL et le module
devient invisible, même à la recherche. Ce module existe pour réparer ce
défaut de plateforme, sans toucher aux modules métier.

La correction est un ``_register_hook``, donc exécuté une fois le
registre complet chargé, après chaque démarrage. Elle fait un seul
UPDATE SQL sur ``ir_module_module`` pour les lignes dont ``module_type``
est NULL, invalide le champ puis journalise le nombre corrigé. Deux
choix non évidents : la valeur n'est écrite que si elle est NULL, donc
un module ``industries`` n'est jamais converti ; et l'écriture passe par
SQL plutôt que par l'ORM, pour ne pas déclencher de logique de module
pendant le chargement du registre.

Le module est caché (catégorie Hidden) et ne pose ni menu ni vue : il
s'installe une fois par base et ne sert aucune fonction métier. Il est
idempotent — un démarrage sans rien à corriger ne journalise rien. La
DESCRIPTION chiffre le défaut mesuré (35 modules sur la maison, 137 en
production le 2026-10-19) ; un module ``industries`` reste hors du
filtre « Applications officielles », conformément au comportement
d'Odoo.

Installation
============

Aucune dépendance externe : le module ne déclare ni dépendance Python ni
binaire (``external_dependencies`` absent) et s'installe comme un module
Odoo standard. Il dépend de ``base_import_module``, installé
automatiquement avec lui.

Aucun ordre manuel et aucune migration : la correction s'exécute à
chaque démarrage, sur les lignes dont ``module_type`` est NULL.

Configuration
=============

Aucun réglage propre, vérifié dans le module : il n'expose ni
``res.config.settings``, ni paramètre système, ni groupe de sécurité, et
son manifeste ne charge aucun fichier ``data``. Il n'y a donc rien à
configurer : la correction s'applique seule à chaque chargement du
registre, et le seul effet visible est la ligne de journal annonçant le
nombre de modules corrigés.

Usage
=====

Rien à configurer : la correction s'applique à l'installation, puis à
chaque démarrage. Le journal l'annonce par une ligne
``module_type « official » donné à N module(s)`` quand il y avait
quelque chose à corriger.

Known issues / Roadmap
======================

La correction ne traite que les types NULL : un module dont
``module_type`` vaudrait une autre valeur n'est pas réparé, et un module
``industries`` n'est volontairement jamais converti. Il n'existe ni
réglage ni désactivation : le seul moyen d'arrêter la correction est de
désinstaller le module.

L'écriture est un UPDATE SQL direct, hors ORM. Elle ne laisse donc
aucune trace dans l'historique des enregistrements, seulement la ligne
de journal « module_type « official » donné à N module(s) » quand il y
avait quelque chose à corriger.

Le module est un contournement assumé : si une version ultérieure d'Odoo
remplit correctement ``module_type`` à l'enregistrement, ce module
devient inutile et peut être désinstallé.
