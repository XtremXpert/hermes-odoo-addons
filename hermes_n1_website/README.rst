Permet à Hermes N1 de lire et de réécrire le **corps** d'une page du
site web (la zone ``<div id="wrap">``), à la demande d'un
administrateur, avec le même contrôle de version et la même trace que
ses autres corrections. La vue QWeb de la page n'est jamais écrite
directement.

Fonctionnement
--------------

- ``hermes.n1.change.lire_page_web(page_id, …)`` renvoie le HTML
  effectif de ``#wrap`` (héritages du site compris), son empreinte
  SHA-256 et, le cas échéant, la raison pour laquelle la page n'est pas
  modifiable par N1.
- ``modifier_page_web(page_id, html, expected_sha256, reason, …)`` :

  - refuse si la page a changé depuis la lecture (empreinte différente)
    ;
  - refuse si la zone actuelle contient du QWeb ou un élément que
    l'assainissement supprimerait (formulaire, iframe, script, svg…) :
    ces pages se modifient dans l'éditeur web ;
  - assainit le HTML reçu : balises QWeb, ``script``, ``iframe``,
    ``form``, champs de saisie, attributs ``t-*``, ``on…``,
    ``data-oe-*`` (métadonnées de l'éditeur qui permettraient d'écrire
    d'autres enregistrements) et liens ``javascript:``/``data:`` retirés
    ;
  - enregistre par ``ir.ui.view.save``, comme l'éditeur web, avec les
    droits du demandeur (``website.group_website_designer`` requis) et
    dans le contexte du site de la page ;
  - consigne l'opération dans ``hermes.n1.change`` avec le HTML d'avant
    et d'après (retour arrière possible) et une note.

Nouvelle page
-------------

``creer_page_web(website_id, name, html, reason, …, add_menu=False)``
crée une page comme « Nouvelle page » dans l'éditeur web
(``website.new_page``, modèle de page vierge), puis remplit sa zone
``#wrap`` avec le même assainissement que ``modifier_page_web``. La
façade générique ne peut pas créer de ``website.page``, dont la vue QWeb
est un objet technique.

- L'adresse vient du nom (« Ente Auth » donne ``/ente-auth``) ; si une
  page ou une adresse existe déjà, la création est refusée : la page
  existante se lit avec ``lire_page_web`` et se modifie avec
  ``modifier_page_web``. Rien n'est jamais écrasé ni dupliqué.
- La page est créée **non publiée** : un humain la relit et la publie
  depuis l'éditeur web.
- ``add_menu=True`` ajoute une entrée au menu principal du site.
- Exige ``website.group_website_designer`` et le droit d'écrire sur le
  site ; s'exécute avec les droits du demandeur et dans le contexte du
  site.
- Consigné dans ``hermes.n1.change`` (avant vide, après : adresse, nom,
  menu, HTML), avec une note. Une demande rejouée ne crée pas de seconde
  page.

Blocs Odoo
----------

Pour composer une page comme dans l'éditeur web, N1 utilise les blocs
d'Odoo :

- ``lister_blocs_web(offset)`` liste les blocs statiques du site
  (``website.s_*``), sans les sous-éléments, fenêtres surgissantes et
  blocs dynamiques (formulaires, cartes, listes d'articles ou de
  produits…) ;
- ``lire_bloc_web(key)`` renvoie le HTML du bloc **rendu par Odoo**,
  avec ``data-snippet`` et ``data-name`` comme l'éditeur l'insère. Un
  bloc qui contiendrait des éléments dynamiques est refusé.

L'assainissement conserve le balisage des blocs (classes ``s_*``,
``data-snippet``, ``data-name``, attributs Bootstrap, options comme
``data-oe-shape-data``) ; seules les métadonnées qui lient un élément au
champ d'un autre enregistrement (``data-oe-model``, ``-id``, ``-field``,
``-xpath``, ``-expression``, ``-type``\ …) sont retirées.

Le demandeur doit être un administrateur en conversation privée avec N1
(règles de ``hermes_n1_audit``). Une demande rejouée ne réécrit pas la
page.

Thème d'un nouveau site
-----------------------

``appliquer_theme_web(website_id, theme, reason, …)`` charge un thème
**déjà installé** (``theme_*``) sur un site qui n'a pas encore de thème,
avec les mêmes étapes que le bouton « Choisir ce thème » d'Odoo, pour ce
site seulement :

- n'installe ni ne met à jour aucun module : l'installation d'un thème
  relève de N3 ;
- refuse un site qui a déjà un thème, car le remplacer retirerait du
  site les enregistrements du thème et leurs personnalisations : ce
  changement se fait dans l'éditeur web ;
- exige ``website.group_website_designer`` pour le demandeur et le droit
  d'écrire sur le site ;
- consigne l'opération dans ``hermes.n1.change``, avec une note. Une
  demande rejouée ne recharge pas le thème.

Dépendances et tests
--------------------

Dépend de ``hermes_n1_audit`` et ``website``.

   ADDONS=addons tools/test-modules.sh IMAGE hermes_n1_website

avec trace et rejeu, l'assainissement, le refus d'une empreinte périmée,
d'une page à QWeb ou à formulaire.

Use Cases / Context
===================

La façade générique de N1 exclut les modèles techniques, et c'est
exactement ce qu'est une page du site : son contenu vit dans l'``arch``
d'une vue QWeb, exécutée côté serveur. Sans module dédié, N1 ne pourrait
donc pas toucher au site. Celui-ci lui ouvre le seul corps éditable
(``<div id="wrap">``), jamais la vue.

Le module travaille comme l'éditeur web, avec les droits du demandeur :
``ir.ui.view.save`` pour l'écriture, ``website.new_page`` pour une page
neuve, ``theme.utils`` pour un thème. Trois garde-fous non évidents :
l'HTML reçu est assaini avant écriture (balises QWeb, ``script``,
formulaire, iframe, ``svg``, attributs ``t-*``, ``on…``, métadonnées
``data-oe-*`` qui lieraient un élément au champ d'un autre
enregistrement) ; une empreinte SHA-256 lue au préalable évite d'écraser
une modification concurrente ; et une page qui contient déjà du QWeb ou
un élément que l'assainissement supprimerait est refusée, renvoyée à
l'éditeur web.

L'ensemble est tracé dans ``hermes.n1.change``, avec le HTML d'avant et
d'après, et rejouable sans effet de bord. Une page créée reste non
publiée : un humain la relit et la publie. Le catalogue de blocs
(``lister_blocs_web``, ``lire_bloc_web``) permet de composer comme dans
l'éditeur, sans exposer les blocs dynamiques. Le demandeur doit être
administrateur en conversation privée avec N1 et membre de
``website.group_website_designer``.

Installation
============

Aucune dépendance externe : le module ne déclare ni dépendance Python ni
binaire (``external_dependencies`` absent) et s'installe comme un module
Odoo standard. Il dépend de ``hermes_n1_audit`` et ``website``,
installés automatiquement ; l'installer après ``website``, comme la
dépendance l'impose.

Aucune migration ni script à lancer. Le module n'ajoute ni menu ni vue :
son effet se voit dans ``hermes.n1.change`` et sur les pages du site.

Configuration
=============

Aucun réglage propre, vérifié dans le module : il n'expose ni
``res.config.settings``, ni paramètre système, ni groupe, et son
manifeste ne charge aucun fichier ``data``.

Les droits sont ceux des modules voisins : le demandeur doit être membre
de ``hermes_n1_audit.group_agent`` (pour la façade) et de
``website.group_website_designer`` (pour écrire sur le site), et l'agent
doit écrire sur le site visé. Si l'un de ces droits manque, l'appel est
refusé (``AccessError``) ; il n'y a donc rien à régler ici, seulement
des groupes à attribuer dans ``hermes_n1_audit`` et ``website``.

Usage
=====

Ce module n'a pas d'impact sur l'interface utilisateur : il n'ajoute ni
menu ni vue. N1 lit et réécrit la zone ``<div id="wrap">`` des pages du
site par RPC, avec les droits du demandeur et la trace de ses autres
corrections.

Une page créée par N1 reste non publiée : un humain la relit et la
publie depuis l'éditeur web. Une page ou une adresse déjà existante
n'est jamais écrasée ni dupliquée : elle se lit puis se modifie. Les
pages qui contiennent du QWeb ou un élément que l'assainissement
supprimerait (formulaire, iframe, script, svg…) se modifient dans
l'éditeur web, pas par N1.

Known issues / Roadmap
======================

Seule la zone ``<div id="wrap">`` est accessible. Une page qui n'en a
pas exactement une est refusée, et une page qui contient du QWeb ou un
élément que l'assainissement supprimerait (formulaire, iframe, script,
svg…) doit être modifiée dans l'éditeur web.

``lire_bloc_web`` rend les blocs avec le premier site par identifiant
(``search([], order="id", limit=1)``) : en multi-site, le rendu d'un
bloc peut donc dépendre d'un autre site que celui de la page visée. Les
blocs marqués dynamiques ou composés ne sont pas proposés au catalogue.

Le thème ne s'applique qu'à un site qui n'a encore aucun thème, et
seulement depuis un module ``theme_*`` déjà installé : ce module
n'installe ni ne met à jour aucun module. Remplacer un thème existant se
fait dans l'éditeur web.

Une page créée reste non publiée et son adresse vient du nom ; une
adresse déjà prise est refusée. Le HTML reçu est limité à 200 000
caractères.
