Crée le compte Odoo de l'agent d'infrastructure **Hermes N3** et le
désactive sur les copies neutralisées de la base.

- L'installation crée l'utilisateur **Hermes N3 Infrastructure**,
  identifiant ``hermes_n3``. C'est un utilisateur interne avec le groupe
  de gestion des contacts, jamais administrateur.
- Le compte n'a pas de mot de passe et aucun courriel de
  réinitialisation n'est envoyé : il ne sert pas aux connexions
  interactives.
- L'agent passe par l'API JSON-2, avec une clé API créée par un humain
  sur la fiche de l'utilisateur. Le module ne crée aucune clé.
- À la neutralisation d'une base (par exemple une copie de production
  restaurée en staging), ``data/neutralize.sql`` supprime les clés API
  du compte ``hermes_n3``, puisqu'elles sont valables sur la production,
  puis désactive le compte. Les autres utilisateurs et leurs clés ne
  sont pas touchés.

Use Cases / Context
===================

L'agent d'infrastructure N3 a besoin d'un compte Odoo pour appeler l'API
JSON-2, mais ce compte ne doit jamais être administrateur ni servir à
une connexion interactive. Ce module ne crée que cela : un utilisateur
interne, ses groupes minimaux et sa neutralisation sur les copies. La
façade et les outils N3 vivent ailleurs (broker Hermes), d'où la
séparation.

Le compte est un enregistrement XML (``data/res_users.xml``) : nom «
Hermes N3 Infrastructure », identifiant ``hermes_n3``, groupes
``base.group_user`` et ``base.group_partner_manager``, sans mot de passe
et avec ``no_reset_password`` — aucun courriel de réinitialisation n'est
envoyé. Le module ne crée aucune clé API : elle est créée par un humain
sur la fiche utilisateur, ce qui garde le secret hors du dépôt et du
code.

À la neutralisation d'une base, ``data/neutralize.sql`` supprime les
clés API du compte puis le désactive, sans toucher aux autres
utilisateurs. C'est la contrepartie de l'API : un staging restauré
depuis la production ne doit jamais pouvoir être piloté par l'agent. Le
module est caché : ni menu, ni vue, ni réglage.

Installation
============

Aucune dépendance externe : le module ne déclare ni dépendance Python ni
binaire (``external_dependencies`` absent) et s'installe comme un module
Odoo standard. Il dépend de ``mail``.

L'installation crée le compte ``hermes_n3`` ; elle ne crée ni mot de
passe ni clé API. La clé est créée ensuite par un humain (voir
Configuration). Sur une copie neutralisée, ``data/neutralize.sql`` est
exécuté par ``odoo neutralize`` ; rien à faire après une
resynchronisation.

Configuration
=============

Après l'installation, un humain crée une clé API pour le compte
``hermes_n3`` (fiche de l'utilisateur, onglet Sécurité du compte) et la
range dans le coffre. Sa valeur ne doit jamais être écrite dans un
dépôt.

Pour réactiver l'agent sur une copie neutralisée, il faut réactiver le
compte et lui créer une nouvelle clé.

Usage
=====

Ce module n'a pas d'impact sur l'interface utilisateur : il ne pose ni
menu ni vue.

L'installation crée le compte **Hermes N3 Infrastructure** (identifiant
``hermes_n3``), visible dans *Réglages* > *Utilisateurs & Sociétés* >
*Utilisateurs*. Ce compte n'a pas de mot de passe et ne sert pas aux
connexions interactives : l'agent passe par l'API JSON-2 avec une clé
API créée par un humain (voir Configuration).

Sur une copie neutralisée de la base, les clés API du compte sont
supprimées et le compte est désactivé ; rien à faire après une
resynchronisation.

Known issues / Roadmap
======================

Le module ne crée ni mot de passe ni clé API : sans intervention
humaine, le compte ``hermes_n3`` ne peut pas s'authentifier. La création
de la clé et son rangement dans le coffre restent des gestes manuels,
documentés dans Configuration.

Le compte est limité à ``base.group_user`` et
``base.group_partner_manager`` ; tout ce qui demande des droits
d'administration doit passer par les outils N3, pas par ce compte. C'est
voulu, mais cela veut dire que l'agent ne peut pas administrer Odoo
lui-même.

Sur une copie neutralisée, les clés du compte sont supprimées et le
compte est désactivé. Pour le réactiver, il faut réactiver le compte
puis créer une nouvelle clé : l'ancienne n'est pas restaurée. Le module
ne pose ni menu ni vue ; son effet n'est visible que dans la liste des
utilisateurs.
