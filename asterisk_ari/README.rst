Click-to-call et suivi d'appels via l'**API ARI** d'Asterisk (FreePBX).

- appel direct depuis la fiche partenaire (bouton « Appeler ») ;
- historique des appels : état, identifiant ARI, erreurs ;
- réglages de connexion et test de connexion.

Le SMS reste géré par le module ``voipms_sms`` (API REST VoIP.ms) : seul
le trafic voix passe par le PBX.

Use Cases / Context
===================

Le click-to-call manquait là où le PBX est un Asterisk/FreePBX : Odoo
savait envoyer des SMS par ``voipms_sms`` et piloter un Wazo par
``wazo_phone``, mais pas composer un appel sur l'interface ARI. Ce
module comble ce seul trou : le trafic voix passe par le PBX, le reste
ne bouge pas. Il est séparé de ``voipms_sms`` parce que le transport,
l'API et les identifiants n'ont rien de commun.

L'approche reste volontairement minimale. Le client ARI
(``services/ari_client.py``) n'utilise que ``urllib`` de la bibliothèque
standard, en Basic auth ``application:jeton``, et se limite aux cinq
appels REST utiles. Deux choix non évidents : un échec d'origination est
écrit sur la ligne d'appel (état Échec, message d'erreur) au lieu d'être
relancé, car un rollback effacerait cet état ; et le raccrochage est un
meilleur effort — si l'appel a déjà fini côté PBX, l'erreur ARI est
seulement journalisée en debug.

Les réglages (URL, application, jeton) vivent dans
``ir.config_parameter`` sous le préfixe ``asterisk_ari.``, et le test de
connexion interroge ``GET /apps``. Le numéro appelé est lu sur la fiche
contact, l'identifiant appelant sur le téléphone de la société courante
: en multi-société, chaque société présente donc son propre numéro. La
fiche d'appel garde le contact en Many2one, sans le posséder : supprimer
le contact ne supprime pas l'historique.

Installation
============

Aucune dépendance externe : le module ne déclare ni dépendance Python ni
binaire (``external_dependencies`` absent) et s'installe comme un module
Odoo standard. Le client ARI n'utilise que ``urllib`` de la bibliothèque
standard.

Le service Odoo doit pouvoir joindre l'API ARI — FreePBX l'expose sur
``http://<hôte>:8088/ari`` — et présenter les identifiants Basic d'une
application ARI. Aucun ordre d'installation particulier : le module
dépend de ``base``, installé avec Odoo.

Configuration
=============

Dans Réglages → **Téléphonie (Asterisk ARI)**, renseigner l'URL ARI,
l'application et le jeton, puis tester la connexion. Les secrets sont
stockés dans ``ir.config_parameter`` (``asterisk_ari.*``), jamais dans
le code.

Usage
=====

Pour utiliser ce module, il faut :

1. Attribuer le groupe **Utilisateur téléphonie** (ou **Gestionnaire
   téléphonie**, qui l'implique) aux usagers concernés.
2. Sur la fiche d'un contact qui a un numéro de téléphone, cliquer
   **Appeler** dans la boîte à boutons : un appel click-to-call est créé
   et lancé vers ce numéro.
3. Suivre les appels dans *Téléphonie* > *Appels* : date, contact,
   numéro, état et identifiant ARI. La fiche d'un appel propose
   **Appeler** (brouillon) et **Raccrocher** (sonnerie ou répondu).
4. Pour préparer un appel sans passer par une fiche contact, créer un
   appel dans *Téléphonie* > *Appels* avec le contact et le numéro, puis
   cliquer **Appeler**.
5. En cas d'échec ARI, l'appel passe à l'état Échec et le message
   d'erreur s'affiche dans le groupe « Erreurs » de la fiche.

La configuration de la connexion ARI est décrite dans la section
Configuration.

Known issues / Roadmap
======================

Le module n'utilise que le REST ARI. Le **WebSocket ARI** (événements en
temps réel : réponse, fin d'appel, puis mise à jour de l'état) est prévu
dans un second temps.
