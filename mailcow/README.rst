Administrer un serveur **Mailcow** depuis Odoo, par son API REST v1
(``X-API-Key``).

- gestion des domaines, boîtes mail et alias du serveur Mailcow ;
- création, mise à jour et suppression sur le serveur par des boutons ;
- synchronisation (import) depuis le serveur Mailcow ;
- mots de passe initiaux et de réinitialisation générés par Odoo,
  affichés une seule fois et jamais stockés, ni dans une fiche ni dans
  un assistant ;
- droits vérifiés dans chaque méthode, pas seulement sur les boutons :
  le groupe Lecture et synchronisation (pour les agents) lit et aligne
  Odoo sur le serveur, sans jamais écrire sur Mailcow ni voir de mot de
  passe ; le groupe Utilisateur crée et met à jour ; le groupe
  Gestionnaire supprime, synchronise et change les mots de passe ;
- une écriture n'est jamais rejouée : après une erreur passagère ou un
  délai dépassé (30 s), le résultat est annoncé incertain, à relire par
  une synchronisation ;
- configuration de la connexion (URL et clé API) dans les réglages ;
- tableau de bord : occupation des domaines, plafonds atteints, pression
  des quotas.

Configuration
=============

Dans Réglages → **Mailcow**, renseigner l'URL du serveur, puis tester la
connexion.

Clé API, de préférence hors de la base : la variable d'environnement
``MAILCOW_API_KEY`` du conteneur Odoo, alimentée par un Secret
Kubernetes copié depuis Vaultwarden. Elle l'emporte sur le réglage, qui
est alors masqué. Elle est ignorée sur une base neutralisée
(``database.is_neutralized``) : un staging cloné n'agit jamais sur le
vrai serveur.

À défaut, la clé saisie dans les réglages est stockée dans
``ir.config_parameter`` (``mailcow.api_key``), donc dans les sauvegardes
et les clones de la base.

Usage
=====

Pour utiliser ce module, il faut :

1. Avoir installé et configuré ``mailcow_tenant`` (URL et clé API du
   serveur) : ce module s'appuie sur ses objets et ses réglages.
2. Attribuer un groupe Mailcow à l'usager — *Utilisateur* ou
   *Gestionnaire* — pour qu'il ouvre le menu *Mailcow*.
3. Ouvrir *Mailcow* > *Vue d'ensemble* : les alertes à traiter
   (plafonds, comptes dormants, alias cassés) s'affichent en cartes ; un
   clic ouvre la liste filtrée correspondante.
4. Choisir l'onglet *Domaines*, *Boîtes* ou *Alias* pour le détail,
   chercher et trier les colonnes ; un clic sur un domaine ouvre son
   tableau de bord, un clic sur une boîte ou un alias ouvre sa fiche.
5. Cliquer **Synchroniser depuis Mailcow** pour relire le serveur, ou
   **Rafraîchir maintenant** pour ne relire que l'état local ; la
   bascule *Rafraîchir tout seul, toutes les 30 secondes* entretient
   l'affichage sans interroger Mailcow.

Sur le tableau d'un domaine, **Nouvelle boîte** et **Nouvel alias**
créent les fiches correspondantes ; **Synchroniser ce domaine** n'aligne
que ce domaine ; **Tous les domaines** revient à la vue d'ensemble. Les
créations, mises à jour et suppressions sur le serveur restent celles de
``mailcow_tenant``.
