Boîte d'envoi de **SMS** par l'API REST de **VoIP.ms** (``api_username``
/ ``api_token``).

- gestion des DID (numéros d'émetteur) du compte VoIP.ms ;
- boîte d'envoi avec segmentation automatique des messages longs (150
  caractères, format ``n/N``) ;
- synchronisation des DID depuis le serveur ;
- configuration de la connexion (utilisateur et jeton) dans les
  réglages.

Use Cases / Context
===================

Diverse-Cité envoie des SMS de service depuis Odoo par le compte VoIP.ms
(API REST v1). ``voipms_sms`` fournit la boîte d'envoi et le registre
des DID émetteurs : on choisit un numéro du compte, on écrit le message,
on l'envoie, et l'historique garde l'état, la date et les identifiants
VoIP.ms.

Deux contraintes du canal façonnent le module. Un ``sendSMS`` de plus de
150 caractères est rejeté : les messages longs sont découpés localement
en segments ``n/N`` sur des limites de mots, et un message de plus de
1600 caractères est refusé avant tout appel. Un numéro NANP est
normalisé en 11 chiffres. L'échec d'un envoi est consigné sur la ligne
(``Échec`` + message) plutôt que levé : un rollback effacerait
l'historique de la tentative, qui est justement ce que la boîte d'envoi
doit garder.

Le client (urllib, sans dépendance) impose son propre ``User-Agent`` —
VoIP.ms répond 403 au ``User-Agent`` par défaut de Python — et n'expose
jamais l'URL dans ses messages d'erreur, car les identifiants y figurent
en clair. Les réglages (``voipms.api_username``, ``voipms.api_token``)
sont dans *Réglages* > *SMS VoIP.ms* et stockés dans
``ir.config_parameter``. Deux groupes : *Utilisateur SMS* pour le menu
et l'envoi, *Gestionnaire SMS* pour la gestion complète. ``wazo_voipms``
réutilise ce client et étend ``voipms.did`` pour router les appels
entrants.

Installation
============

Aucune dépendance externe : le client de l'API VoIP.ms est écrit avec
``urllib`` de la bibliothèque standard, et le manifeste ne déclare ni
``external_dependencies`` Python ni binaire. Le module dépend de
``base`` et s'installe comme un module Odoo standard. L'instance doit
pouvoir joindre ``https://voip.ms/api/v1/rest.php`` en HTTPS sortant ;
les identifiants se renseignent après installation, dans *Réglages* >
*SMS VoIP.ms*.

Configuration
=============

Dans Réglages → **SMS VoIP.ms**, renseigner l'utilisateur et le jeton
d'API, puis tester la connexion. Le jeton est stocké dans
``ir.config_parameter`` (``voipms.*``), jamais dans le code.

Usage
=====

Pour utiliser ce module, il faut :

1. Attribuer le groupe **Utilisateur SMS** (ou **Gestionnaire SMS**, qui
   l'implique) aux usagers : le menu *SMS VoIP.ms* est réservé à ce
   groupe.
2. Ouvrir *SMS VoIP.ms* > *DIDs* et cliquer **Synchroniser depuis
   VoIP.ms** sur une fiche DID : la liste locale est alignée sur les
   numéros du compte VoIP.ms, avec *SMS disponible* et *SMS activé*.
3. Créer un message dans *SMS VoIP.ms* > *Boîte d'envoi* : choisir le
   *DID (émetteur)*, saisir le *Destinataire* (numéro NANP, 10 chiffres
   ou préfixe ``1``) et le *Message*, puis cliquer **Envoyer**.
4. Un message de plus de 150 caractères est découpé en segments
   numérotés ``n/N`` ; un message vide, non NANP ou de plus de 1600
   caractères est refusé avant tout appel.
5. La boîte d'envoi garde l'historique : état, date d'envoi,
   identifiants de message VoIP.ms et, en cas d'échec, le message
   d'erreur.

Le jeton et l'utilisateur de l'API se règlent dans Réglages (voir
Configuration).

Known issues / Roadmap
======================

Limites connues
---------------

- **Pas d'accusé de livraison** : l'état passe à ``Envoyé`` dès que
  ``sendSMS`` répond ; le module ne relit jamais le statut de remise
  (aucun appel de statut dans le client).
- **Pas de SMS entrants** : le client n'appelle que ``sendSMS``,
  ``getDIDsInfo`` et ``getBalance`` ; aucun message reçu n'est rapatrié.
- **Synchronisation des DID fiche par fiche** :
  ``action_sync_from_provider`` part d'une fiche DID et aligne toute la
  liste, mais les menus n'exposent pas de bouton global de
  synchronisation.
- **Identifiants en clair** : ``voipms.api_username`` et
  ``voipms.api_token`` sont des champs de réglages stockés dans
  ``ir.config_parameter``, et l'API les transporte en paramètres d'URL
  (requête GET), sans en-tête.
- **Segmentation bornée** : 150 caractères par segment, 1600 au total ;
  un mot plus long qu'un segment est coupé au milieu du mot.
- **Aucune tâche de fond** : pas de cron ni d'envoi différé ; un
  brouillon n'est envoyé que par *Envoyer*.
- **Statut ``Beta``** : ``development_status`` vaut ``Beta``.
